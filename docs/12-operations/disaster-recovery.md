# Disaster Recovery

## Scenario: Corrupted SQLite database

1. Stop the stack: `docker compose stop backend`
2. Restore the latest backup of `llm_data` volume (see [`backup-recovery.md`](./backup-recovery.md)).
3. Restart the stack: `docker compose start backend`
4. Verify health: `curl http://127.0.0.1:8000/healthz`

## Scenario: Lost artefacts volume

ONNX artefacts can be regenerated by re-running the training jobs from the original datasets,
which are stored as CSV files under `LLM_DATA_DIR/datasets/`.

## Scenario: Backend binary corruption

1. Stop the stack: `docker compose stop backend`
2. Rebuild the backend image: `docker compose build backend`
3. Restart: `docker compose start backend`
