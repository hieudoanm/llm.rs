Everything happens locally.

Your CSV and trained artefacts never leave your machine. Datasets, jobs, metrics, and models persist to local SQLite storage.

Six task types

Classification, regression, semi-supervised, clustering, anomaly detection, and offline RL share one workflow.

Local-first and private

No uploads, no API keys, no accounts. Everything persists to a local SQLite database on your disk.

ONNX is the contract

Every successful job exports a portable .onnx model that runs in any ONNX-compatible runtime, independent of the training code.

Two surfaces, one engine

A native desktop app for the visual workflow, or the llm CLI for scripts and headless training — same Rust core underneath.

Jobs and metrics

Every training run is a tracked job with accuracy, F1, and loss metrics you can inspect and compare.

Offline reinforcement learning

Train RL policies without a simulator service — environments run locally alongside the model.

See it in action

How the CLI works

CSV in, ONNX out — a three-step local pipeline.

01

Register a dataset

Point llm at a CSV file. Columns, types, and labels are inferred and stored in the local dataset registry.

llm dataset data/iris.csv
02

Train a job

Pick a task and algorithm, choose features and label — the job runs locally and records metrics as it goes.

llm train --task classification …
03

Export ONNX

A successful job exports a portable .onnx model that runs in any ONNX-compatible runtime — no Rust required downstream.

llm export --job-id … --output model.onnx
